# 弦号提示词与二次核验实验

## 目的

上两轮新方案在这两个小节上按发声列忽略弦号可匹配 19/20 个品位，弦号、品位、列号一起匹配仅 7/20，完整事件 3/16。四次返回的记号内容相同。因此这轮先隔离弦位置问题，而不是继续增加节奏和技巧规则。

“提示词不足”是待检验假设，不能提前认定它是唯一原因。这轮不更换模型、不标注图片、不改变裁剪或使用人工答案提示。

## 四次调用

| 请求 | 方法 | 要检验的问题 |
|---|---|---|
| A | 短提示词，从上向下逐弦 | 去掉多任务后能否正确读出各弦品位？ |
| B | 从最下方第6弦向上独立读取 | 改变定位锚点与读取方向是否有帮助？ |
| C | 附上原图与 A 的草稿，从下向上核验 | 二次检查能否修复错误，是否会误改正确结果？ |
| B 重复 | 新请求，不带其他答案，再次从下向上读取 | 同一提示词的输出是否稳定？ |

“独立”指请求不携带此前的答案，不代表同一个模型的错误在统计上互不相关。C 的草稿只取 A 的原始逐弦内容，不取本地评分、参考答案、期望品位或错误位置。每次请求及 C 的实际草稿文本都记录在 configuration.json。

固定参数：deepseek-flash、thinking disabled、temperature 0、detail original、max_tokens 8192。最多 4 次请求，不自动重试或无限自查。格式、网络或截断错误会停止后续请求。

## 提示词改变

共用系统提示词只定义六根物理横线与字符读取规则。用户提示词分别规定读取方向或草稿核验任务。强调数字中心对应哪根横线、白色遮挡处观察左右延伸线、两根 E 位于上下两端；不按旋律/低音模式把六根弦缩成少数行。

输出只有小节号、六根弦的品位序列和待确认项，没有节奏、列号、起点、技巧或置信度。无音符为 []，整根弦无法辨认为 null，单个品位未知为列表中的 null。

## 如何判断效果

- 完整弦行匹配：12 根弦行的品位序列逐行比较，包含空行。
- 有音符的弦行匹配：单独列出参考中 9 根非空弦行，避免空行掩盖错误。
- 按弦顺序匹配音符：每根弦使用保序匹配，不假设发声列，总共 20 个参考音符。重复数字不能被重复计数。
- 忽略弦号的品位数量匹配：只核对每小节的数字库存，不能证明位置或顺序正确。
- 核验修正与误改：C 对 A 修正了多少错误弦行、破坏了多少原本正确弦行、总匹配音符数是否上升。

这些指标不涉及发声列，不能直接与上轮 7/20 的“弦/品/列同时正确”比较，也不能把诊断通过当作可播放的乐谱。

若 B 优于 A，可以继续验证反向锚点；若 C 优于 A 且少有误改，可以进一步测试核验流程。若 B 与 C 一致但都错，不能把一致当作正确。若这些简化与核验都无改善，再增加弦编号或程序定位，作为另一项输入辅助实验。

## 自查的边界

同一模型再次检查可能沿用草稿中的错误，因此我们记录误改，而不假定第二次答案更可靠。相关推理任务的研究也观察过无外部反馈的自纠退步：[Large Language Models Cannot Self-Correct Reasoning Yet](https://arxiv.org/abs/2310.01798)。该研究不直接评估吉他谱视觉识别，本项目仍以图像对照结果为依据。
