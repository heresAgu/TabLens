# 本地吉他谱识别实验

这是小规模识别实验，还不是完整播放器或乐谱编辑器。

当前阶段优先验收弦号、品位、先后顺序和同时发声；节奏允许后续人工编辑，演奏技巧暂缓。`note_positions` 模式将音符读取与节奏完全分开，复用通用分格提示词和独立逐弦复核，有分歧才调用局部卡片复核，每轮最多3次请求。目标图片及裁剪位置由 `note_positions_target.json` 提供，不将曲名、人工品位答案或正确音符数写进提示词。当前输入仍须为人工选择的清晰水平谱行，尚未实现通用整页定位。

2026-09-28 跨谱测试的 Duvet 第1、2小节两轮主读数均31/31弦品位置、31/31发声分组；这两个小节均为单音。Lullaby 已保存结果按同一音符评分重新核对为20/20弦品位置、16/16发声分组、4/4同时弹。Duvet 的逐弦核查曾数错重复音或误读邻弦残片，局部卡片两轮均确认原分格结果，无需改音；保留核查分歧，并另存 `review_resolution.json`、`note_positions_resolved.json` 记录局部证据如何解决误报。这里的重新合并不发API请求。下一步进入乐谱显示与音符/节奏纠错，不以复杂节奏识别为前置条件。

整组放大和固定灰度提亮都已完成一轮API测试但未改善，实际结果见`BEAM_GROUPS_RESULTS_20260928.md`、`BEAM_CONTRAST_RESULTS_20260928.md`。当前已准备`rhythm_beams_verified`：初次读取后用原图像素候选发现横梁分歧，有分歧才让模型复核，每轮最多4次；设计和117项本地验证见`BEAM_VERIFICATION.md`。像素候选在已知两小节上20/20正确，新的模型复核效果尚待实际请求确认。

现在可打开`启动自动实验会话.cmd`，在本地输入密钥并“连接实验会话”。后续由Codex提交有上限的任务，窗口内存保留密钥，实验代码可重新加载，通常不必每轮重新粘贴。任务文件不含密钥。说明见`API_SESSION.md`。原手动实验窗口仍可用。

三轮混合节奏实际结果见`RHYTHM_RESULTS_20260928.md`：错误集中在三层横梁少读一层，局部卡片还缺少附点上下文。随后`rhythm_prompt_compare`用同一完整谱图、同一用户提示词与参数，只改变系统核查规则，共4次；一轮实际结果见`PROMPT_COMPARISON_RESULTS_20260928.md`，第1小节时值7/10提高到8/10，第4小节仍8/10，完整时间轴均未通过。随后整组4倍放大对照`rhythm_groups_compare`也已完成一轮：第1小节8/10降到7/10，第4小节仍8/10，见`BEAM_GROUPS_RESULTS_20260928.md`。下一步只改变整组图亮度，完整上下文继续保留。

双击 `启动识别实验.cmd`，在本地窗口的密码输入框粘贴 DeepSeek 官方 API Key，再点击开始。默认模型为 `deepseek-flash`，默认“混合节奏诊断”发送4次请求。

默认“混合节奏诊断”读取第1、4小节，分别对比完整谱行与符干局部放大卡片，共4次；只评估横梁、时值、起点，不评估音高或同时弹，不生成完整播放文件。设计与当前定位范围见`MIXED_RHYTHM.md`，已完成的三轮API结果见`RHYTHM_RESULTS_20260928.md`。

“独立核查实验”已两轮实际通过第2、3小节：初始19/20音符和15/16事件，局部复核后均20/20和16/16，同时弹4/4，且只改了漏掉的一个0品，见`VERIFICATION_RESULTS_20260928.md`。这套流程保留在下拉框，作为成功基线：先按格读数字、独立读节奏，再用分弦条带独立读取每弦品位顺序；有候选才用原图放大卡片复核，共3～4次。未消除的分歧标记待确认。设计见`CELL_VERIFICATION.md`。

旧“分格结构实验”仍保留：模型读六行网格，程序按格子行列确定弦与发声位置，节奏独立读取，两步各重复一次，共4次。两轮实际得到四份结果：三份19/20音符位置、15/16完整事件，一份20/20与16/16；同时弹均4/4、节奏均16/16。三份有误结果均遗漏第2小节3弦末尾0品。实际分析见`CELL_RESULTS_20260928.md`，分格设计见`CELL_PIPELINE.md`。

上一轮“同时弹与先后顺序”模式也保留：模型将分弦图数字对应到下方发声列标签，程序与独立节奏观察合并，详见`EVENT_PIPELINE.md`。实际两轮结果为弦品20/20、发声位置17/20、同时弹2/4、完整事件10/16。评分已修正为分组与节奏独立检查，节奏实际16/16；原报告14/16是评分程序提前跳过空音符列造成的统计错误。原始文件保留，修正报告另存为`report_reevaluated.html`，详见`EVENT_RESULTS_20260928.md`。

下拉框保留“弦定位辅助实验”（原图、坐标、边缘弦号、分弦展示）和“弦号提示词实验”（正向、反向、核验草稿、反向重复），各4次；二次核验只提交第一份模型草稿，不提供人工答案或评分。还可选择“记号方案对照”（原提示词一次＋记号两次）和旧版“整页一次＋裁剪两次”，各3次。模型、非思考模式、temperature=0、原图detail和输出额度固定。少量请求仅用于初步判断，不自动追加实验。

请求按服务商用量计费。当前使用非思考模式；遇到空输出、截断或接口错误会停止后续请求，不自动重试。密钥仅在窗口存活期间保留在内存中，方便再次运行，关闭窗口后忘记，不保存到项目文件、请求日志、命令行参数或报告中。

结果写入 `runs/日期时间/`，包括每次的实际提示词、原始返回、解析结果、逐事件对照和 `report.html`。新运行还会保存实际提交的图片副本 `inputs/`，以及图片大小和 SHA256，报告可展开查看每次输入。记号方案额外保存 `_symbols.json`，转换后的 `_prediction.json` 包含待确认项及来源引用。报告分别展示按弦品位顺序、弦/品/列匹配和完整音乐事件，避免把事件正确率误称为字符识别率。窗口中可以打开报告。

逐弦实验保存 `_strings.json`，不生成播放乐谱。报告比较完整弦行、非空弦行、按弦顺序匹配音符数，以及核验修正与误改的弦行数。这个诊断不读取时间列，因此匹配数不能与上轮“弦/品/列”指标直接比较。读取格式错误时停止后续请求，不花额外调用核验无效草稿。

当前只换算单一节奏序列。未知时值会使同小节后续起点保持 null，不通过凑拍补全；多声部、连音组及尚未解释的连接会标记待确认。结构检查通过不代表模型识别正确。关闭窗口会停止后续请求；已经发送的请求仍可能计费。

实验统计的是这两个小节的探索性结果，不能据此推断其他歌曲、复杂技巧或整页扫描的准确率。两个小节合计 16 个音乐事件、20 个音符；同时发声的音构成一个事件。

## 检查与准备

```powershell
python experiments/recognition_lab.py --prepare-only
python -m unittest discover -s experiments -p "test_*.py" -v
```

时间采用全音符为 1 的精确分数：八分音符为 `1/8`，4/4 普通小节为 `1`。品位按相对变调夹表示，模型不得预先加上变调夹品数。

流程与限制见 `SYMBOL_READING.md`；提示词在 `prompts/visual_evidence_system.txt` 与 `prompts/visual_evidence_reading.txt`。`symbol_schema.json` 是输出约定，`symbol_reader.py` 负责校验和转换。修改 Python 后，旧手动实验窗口须重开；新的自动会话会在任务开始时重新加载实验代码。提示词文本在每轮开始时读取。

弦号提示词与二次核验设计见 `STRING_VERIFICATION.md`；提示词为 `prompts/strings_system.txt`、`strings_forward_user.txt`、`strings_reverse_user.txt` 和 `strings_review_user.txt`。

最新两轮结果与定位辅助实验见 `STRING_ANCHORS.md`。新增提示词为 `prompts/strings_coordinates_user.txt` 和 `strings_panels_user.txt`，图片辅助由 `string_anchors.py` 生成。横线检测只针对当前清晰、水平、单行六线谱；检测不到恰好六根等距长横线就停止，不能视为通用谱页预处理器。

两轮定位辅助实验（`143904-e9c67d`、`143916-290c6e`）中，分弦展示均匹配12/12根完整弦行、9/9根非空弦行和20/20个按弦顺序排列的品位，返回数量均为20。这个结果仅覆盖品位、所属弦及弦内顺序，不代表节奏和完整音乐事件已经正确。后续验证顺序见 `NEXT_VALIDATION.md`。
