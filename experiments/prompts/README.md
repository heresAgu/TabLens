这些新提示词已经准备好，尚未调用 API 测试。历史结果保持原样；实验工具已接入记号方案。它们是针对当前六线谱排版的假设，效果需要通过实验验证。

## 第一项：只读取每根弦上的品位

使用 diagnostic_string_reading.txt 与同一张第 2、3 小节裁剪图。暂时去掉 metadata、节奏、起点和 JSON 乐谱组装，只检查数字及弦号。

这项实验用于区分错误环节：如果弦号仍错，重点在视觉定位；如果按弦读取正确而完整转写错误，重点在音符分组、节奏解析或多任务干扰。不能把诊断结果称为完整乐谱识别准确率。

## 第二项：同图比较原提示词与 v2

原提示词保存在上一轮 configuration.json 和 recognition_lab.py 中。新版本由 v2_system.txt 与 v2_user.txt 组成，输出格式保持兼容。

固定模型 deepseek-flash、thinking disabled、temperature 0、max_tokens 8192、detail original，以及相同的页头与谱行图片；只改变提示词。建议原版和 v2 各重复 3 次，共 6 次请求。先比较这两个小节，验证提示词是否改善；不要将整个两小节的人工答案或期望事件数量写入模型输入。

分别检查弦号与品位、同时发声分组、小节时值与结构、完整事件一致数、额外或遗漏事件。上一轮完整事件是按序号比较，遗漏与额外事件会影响后续对齐，不能将它等同于字符 OCR 准确率。

## 第三项：验证是否能迁移

如果 v2 在这些小节上改善，用未参与提示词修改的小节验证，例如第 1、4 小节里的混合八分、十六分与三十二分节奏。避免仅适应两个全为八分音符的小节。谱图标注弦号或改换模型应另做实验，不要与提示词修改混为同一个变量。

## 补充诊断：读取可见记号，暂不计算时间

visual_evidence_system.txt 与 visual_evidence_reading.txt 组成 tab-symbols-v1 提示词：先按六根弦记录品位，用列号归并同时发声音符，再读取逐列的符干、横梁、符尾、附点和连接。不让模型输出 onset、duration 或 tick。完整 JSON 约定在 ../symbol_schema.json。

实验窗口的“新方案对照”使用相同裁剪图：原提示词直接转写一次，记号方案两次，共 3 次 API 请求。symbol_reader.py 将记号换算成旧评分器可比较的乐谱，报告额外比较每根弦的品位顺序与音符位置。按弦顺序相符不代表发声分组或节奏正确；结构校验通过也不代表识图正确。

横梁层数需逐个符干检查：三层为三十二分音符，同组不同符干可能有不同层数。通过这项诊断，可以区分视觉读错与时值换算错误；程序换算无法修复已经读错的横梁或弦号。

网页端对话里的第 2、3 小节与现有人工参考一致；第 1、4 小节的三十二分音符结构也已对照原始图片检查。这些答案只用于人工校验，不加入待测模型的提示词。
