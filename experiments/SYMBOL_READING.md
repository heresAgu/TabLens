# 读取记号，再生成乐谱

本方案是可测试的识谱实验，还没有证据证明它比原提示词准确。当前只处理规整六线谱的单一节奏序列。

## 1. 模型负责读到的东西

模型先按从上到下的六根弦，逐行记录品位；每个品位包含发声列号。不同弦上的同时发声音符共享列号。品位只保存一次，不在节奏列重复一份。

每个列号对应一份节奏观察：符干是否可见、横梁层数、符尾层数、附点、明确的长时值记号或休止符。短横梁要逐个符干读取，不能将整组最大层数套给所有音。

无法定位的数字保存在 unassigned_notes。看不清的字段为 null，原因保存在 uncertain_items。弧线、滑线和 H/P 等文字保留起止位置，不因品位变化直接推断演奏技巧。

提示词分两份：visual_evidence_system.txt 给通用读取规则，visual_evidence_reading.txt 指定本轮第 2、3 小节及 JSON 格式。示例均使用虚构小节，不含待测小节答案。

## 2. 程序负责可重复的换算

所有计算采用精确分数，以全音符为 1。明确符干、无横梁或符尾的普通音符为 1/4；一层为 1/8，二层为 1/16，三层为 1/32。附点按照已读取的数量换算。数字 0 本身不能推出任何时值。

单一节奏序列从小节内起点 0 开始，逐列累加时值。同一列的多个音符共享谱面节奏；这不代表其实际吉他声音都必须同时停止。转换结果属于乐谱候选，不是已经验证的音频演奏。

不知道某列时值时，该列 duration 为 null，其后各列 onset 为 null；下一小节重新计算小节内起点。程序不凭小节剩余拍数填补未知值。完整小节按拍号检查长度；弱起和完整小节分别标记。未知完整性、多声部和不支持的节奏保留待确认状态。

原始记号和程序生成的乐谱分文件保存，便于检查是视觉读取还是转换出错。每个音符附有本次识别内的 ID 和小节、弦行、行内序号、列号来源；目前没有像素框定位或可交互纠错界面，也不承诺这些来源 ID 跨重新识别保持不变。

## 3. 检查不会改变观察结果

格式错误包括：六根弦没有按顺序各出现一次、列号不连续、重复列引用、引用不存在的列、字段类型错误。遇到这些问题会保存原始返回并报告，不能当作成功换算。

内容冲突包括：休止列仍有品位、一个符干同时报告横梁和符尾、长时值记号与横梁冲突、小节溢出、未定位品位、未知时值和未解释连接。保留观察与待确认原因，不自动移弦、删音、补音或猜测技巧。

ready_for_playback 仅表示本转换器的结构检查通过，不表示音符、弦号或节奏与图片一致。错误但内部一致的乐谱也可能通过检查，因此仍需人工对照和实验评分。

## 4. 对照实验

新窗口默认发送相同页头与谱行图：旧提示词一次，记号方案两次。模型、图像原始 detail、非思考模式、temperature=0 和输出额度固定。每次保存具体提示词与哈希，参考答案仅用于本地比较。

报告分别看三层结果：每根弦的品位序列是否一致；弦号、品位与列号是否匹配；转换后整个事件的音符组合、起点与时值是否正确。空弦行也计入整行比较，所以这个指标不是字符 OCR 准确率。

先检查第 2、3 小节的弦定位和同时发声，再用其他小节检查混合横梁。第 1、4 小节已经参与过规则讨论，可用于后续功能测试；真正衡量泛化还要增加未用于调整提示词的其他曲谱。不能仅凭这两个全八分音符的小节声称复杂节奏已经识别可靠。

## 5. 当前限制

- 多声部暂不自动计算起点；同时开始但有独立谱面时值的音符不能压成同一份节奏。
- 连音组、倚音、重复展开和节奏变化尚未自动转换。
- 弧线、H/P、滑线等连接保留，暂不驱动特殊技巧播放。
- 非 4/4 中全小节休止的语义需要进一步区分，不凭 whole 休止符自动套用整小节时长。
- 这里读取的是谱面时值，实际发声衰减、let ring、止音与演奏表达留给播放层。
