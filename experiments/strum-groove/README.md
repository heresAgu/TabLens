# 连续扫弦 A–K 试听

在项目根目录运行 `python experiments/strum-groove/prepare_layers.py`，然后运行 `node experiments/strum-groove/render.mjs`。前一步从本地原始 AIFF 提取本次试听所需的轻奏、重奏音符，后一步调用 TabLens 当前的乐谱和播放计划，在 `experiments/.runtime/strum-groove/` 生成 WAV。两个脚本只写入已忽略的实验目录，不修改应用、正式音源或乐谱文件。

十一段使用同一段 96 BPM、四小节的 C→G 扫弦，音符、扫弦方向和节奏完全相同。A 是改进前的播放，B 仅增加每小节内的主次重音，C 在 B 的基础上微调单次扫弦内部的弦间距、触弦力度与起音，并在新小节前略收尾音。D 继承 C，把上扫换为轻奏录音；E 在 D 的基础上把每小节靠后的重拍下扫换为重奏录音。用户反馈 D 更自然、E 太重，但 D 的上扫太轻。F/G 因此继承 D，仅在上扫叠加 0.14 秒的中力度清晰起音，分别为原力度的 45% / 70%。用户反馈 F 的音量合适，但快扫中间的延音过短。H 保持 F 的起音力度，让辅助层自然衰减到下一次同弦触弦；I 再让旧音以低电平跨过下一次触弦约 55 毫秒。用户认为 H/I 听起来差不多，正式播放器采用不额外叠音的 H。J 使用正式播放器的音源实现，但保留实验中的节奏强弱和微小时间变化，用于核对移植是否一致；K 则完全按当前播放器生成，供实际听感对照。D–K 与 C 的整段 RMS 响度一致，排除整体音量差异。每次扫弦的第一根弦仍落在原拍点。

J 与 H 的波形差异 RMS 约 0.00027（H 自身 RMS 约 0.06624），说明轻奏采样和辅助延音已经接入。K 没有实验时人为指定的六下重音，因此它是检查网页默认播放听感的主要文件。原始素材按力度分组，没有独立的上下扫录音，因此此实验还不能解决真实拨片上下方向的全部音色差异。
