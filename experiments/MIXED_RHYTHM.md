# 第1、4小节混合节奏诊断

默认模式`rhythm_diagnostic`，每轮4次调用，没有自动重试：第1小节完整谱行、同小节符干放大卡片、第4小节完整谱行、同小节符干放大卡片。两种输入复用已经成功的节奏系统提示词；用户提示词分别说明谱行或卡片的定位方式。

## 为什么要继续测节奏

第2、3小节核查已两轮达到20/20音符位置、4/4同时弹和16/16完整事件，见`VERIFICATION_RESULTS_20260928.md`。但这两小节全部为八分音符，无法验证同组横梁中时值不同的情况。

第1小节最后一拍、第4小节第二拍都有短横梁。人工参考依据每根符干连接的横梁转写，分别包含八分、三十二分、三十二分、十六分，采用全音符为1的精确分数。参考在`reference_rhythm_1_4.json`，只用于评估，不进入提示词、定位、卡片或API请求。这些小节已在之前讨论，不能称为未见测试。

## 定位与图像

当前谱页的第1、4小节区域仍手动指定裁剪范围；裁剪后弦线、小节边界和符干位置从像素检测，不使用参考事件数量。定位不是通用整页分割器。

准备时发现旧符干条件把第4小节三层短横梁的连续深色区域当成一个宽符干，合并了两个位置。新诊断模式要求更长的竖直深色连续段：至少平均弦距的1.4倍，排除本谱三层横梁形成的较短竖向块。检测条件记录在定位文件`stem_min_run`中。第2、3小节旧模式仍使用原0.9倍条件，保持成功基线。

两小节当前各检测到10根符干。完整图只在新增空白处添加标签，谱面像素不变。卡片取目标符干与相邻符干中点之间的原图，纵向从下方符干搜索区域开始，最近邻放大3倍。标识和蓝色指示线放在原图片段外；每个卡片保留目标符干附近的横梁连接情况。卡片布局由检测位置决定，不包含横梁答案、时值或正确节奏序列。

新条件仍只适用于当前水平谱行、向下且足够长的符干；更短符干、拥挤排版、休止、多声部和长时值记号需要扩展。卡片只保留下面的节奏区域，上部的品位及连接技巧另行识别。

## 记录和评价

模型仍输出实际记号：符干、每根符干连接的横梁层数、符尾、附点、休止等。程序校验与图像标签一致，使用现有记号换算器得到时值并累加起点。未知时值使后续起点保持null，不通过凑满4/4补值。

每份结果分别报告记号、时值、起点、时值与起点同时正确的数量，以及整小节时间轴是否有效。两个小节各10个节奏位置。该报告不加入参考音符，不评估弦品、同时弹或演奏技巧，也不生成完整播放乐谱。

保存实际输入副本、提示词、大小和SHA256，原谱行副本`source_m1.png`/`source_m4.png`，定位及卡片变换`rhythm_anchors_m1.json`/`rhythm_anchors_m4.json`，原始响应、`_rhythm.json`及程序换算的`_timing.json`。卡片复用完整谱行请求的系统提示词，画像和用户说明同时改变，所以差异不能单独归因于提示词。

本地测试验证短横梁不会合并两个长符干、真实裁剪保留像素、未知时值传播、非法列停止及报告范围。已完成三轮API实验，实际结果见`RHYTHM_RESULTS_20260928.md`；密集横梁仍会少读，下一轮使用同一完整图只对比提示词。

## 运行

窗口为“吉他谱节奏实验 · 短横梁与混合时值”，选择“混合节奏诊断”。本地粘贴密钥并开始，一轮4次请求，暂不需要重复第2、3小节实验。旧“独立核查实验”保留在下拉框。

```powershell
python experiments/recognition_lab.py --prepare-only
python experiments/recognition_lab.py --mode rhythm_diagnostic
```

下一步依据实际结果选择保留完整图、局部卡片或二者核查，再将验证过的节奏与音符位置及连接记号合并，最后测试未参与调试的新谱图。
