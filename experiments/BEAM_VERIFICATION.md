# 原图像素候选与模型横梁复核

模式`rhythm_beams_verified`，每轮最多4次API调用，不重试。处理Lullaby第1、4小节的横梁分歧。第2、3小节音符识别成功基线保留，本轮仅评估节奏。

同图提示词、整组放大、固定灰度提亮都没有完全解决密集横梁，最新实际结果见`BEAM_CONTRAST_RESULTS_20260928.md`。本轮把横梁的位置提取交给可检查的图像程序，模型对照原图复核候选，不再只要求模型直接报一个层数。

## 依据像素产生候选

1. 弦线、符干及相邻符干的连接仍由原图检测。对每对相邻符干之间扫描原始灰度，沿纵向记录像素中位数。
2. 灰度小于160形成粗略墨迹区间。区间内部若存在比两侧至少亮8的起伏，且两侧都有至少3行较暗墨迹，则将其记录为可能的层间分隔。
3. 没有测得分隔的大黑块不按典型厚度拆成多个梁；过宽、过窄或没有足够连接证据的结果保留未知。宽度限制以弦间距换算，只用于拒绝含糊的候选，不用它直接计算层数。
4. 根据条带实际连接的两个端点符干，分别得到每根符干的候选层数。只比较目标符干左右相邻的条带，不能用整个横梁组的最大层数替代所有符干。

候选模块`beam_evidence.py`不读取参考乐谱、拍号、时值或之前模型错误的位置。输入是原图、已经检测的弦线/符干坐标和连接范围。参数来自当前谱例的探索性灰度观察；尚未验证其他字体、尺度和图像质量。

当前原图中两小节候选层数分别为`[1,1,1,1,1,1,1,3,3,2]`和`[1,1,1,3,3,2,1,1,1,1]`。与人工参考比较为20/20。数组来自像素计算，不是构造图片或候选时读取参考；参考仅供本地评分。这不是模型API结果，也不是新谱上的泛化准确率。

## 最多四次调用

1. 第1小节初次读取：图片、提示词与上一轮该小节的提亮条件完全一致。
2. 将初次模型层数与像素候选比较；有分歧才对该小节复核，无分歧跳过付费请求。
3. 第4小节独立初次读取。
4. 同样有分歧才复核第4小节。

初次请求不提供候选。复核时提交该轮真实模型草稿、待核查位置、从像素得到的条带y范围和层间灰度起伏，以及相同的原图上下文。用户提示词为`rhythm_beam_review_user.txt`。不提交人工答案、正确时值或评估得分。

程序候选可能错误，复核要求以原图为准，不能照抄候选。模型只能修改目标列的beam_count及这些列的uncertain_items，其他字段逐字段保持。修改页头、附点、声部、非目标列等即拒绝并停止后续请求。

模型可保留原判断或改为null。候选不会被自动覆盖到节奏结果；复核未消除的分歧继续显示，未知时值依旧让后续起点保持null。完整小节总时值只用于检查，不用于补答案。

## 保存和检查

每轮冻结`beam_candidates_m1.json`/`beam_candidates_m4.json`、原图、定位及灰度证据。候选记录每段墨迹范围、内部亮度起伏、扫描坐标、参数、连接端点和未知原因。

初次与复核分别保存原始返回、记号、时值/起点。报告显示像素分歧、未知候选、实际改写和逐列节奏评分。初次错误不会被最终结果覆盖。

117项本地测试通过。覆盖暗缝分层、噪声不误拆、大黑块保留未知、相邻符干绑定、真实裁剪、目标外修改拒绝、不自动采用候选、无分歧跳过调用以及失败后停止。GUI和本地会话预检通过；初次输入字节及提示词与上一轮提亮条件相同。

模型复核效果尚待真实API验证。当前只支持水平谱行、向下符干、连接到相邻符干的完整横梁；孤立符尾、半长短横梁、多声部、休止及整页自动分割仍未覆盖。通过这两个小节后要固定算法参数，在未参与调试的新谱例上验证，再合并音符、节奏和连接技巧。
